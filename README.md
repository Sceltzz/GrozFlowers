# Groz Flowers

Лендинг флористической мастерской. React + Vite + TypeScript + Tailwind CSS v3,
иконки только из `lucide-react`.

```bash
npm install
npm run dev      # http://127.0.0.1:5173
npm run build    # прод-сборка в dist/
npm run preview  # посмотреть собранное
```

## Структура

```
src/
  App.tsx                    порядок секций — прямой, без отрицательных отступов
  index.css                  токены, .liquid-glass, кейфреймы, reveal
  components/
    Navbar.tsx               плавающая пилюля; тон берёт из useGroundTone
    Hero.tsx                 первый экран во весь вьюпорт
    Ribbon.tsx               лента на стыке секций — см. «Стыки секций» ниже
    FeaturedConfigurator.tsx интерактивная витрина — см. «Конфигуратор» ниже
    Catalog.tsx              витрина: фон-фото под кремовой вуалью + сетка карточек
    Advantages.tsx           «Почему мы» на глубоком зелёном
    Footer.tsx               фиксированная нижняя панель; две подложки в кросс-фейде
    ui/
      magnetic-link.tsx      наведение увеличивает пункт шапки — см. ниже
      animated-dock.tsx      референсный компонент, в шапке не используется — см. ниже
  data/
    media.ts                 ВСЕ фото проекта — один файл
    products.ts              букеты витрины
    featured.ts              данные конфигуратора (размер/цвет/упаковка/цена)
  hooks/
    useScrollReveal.ts       IntersectionObserver, threshold 0.15, срабатывает один раз
    useGroundTone.ts         на светлом фоне сейчас панель или на тёмном
  lib/
    utils.ts                 cn() — clsx + tailwind-merge, стандартный shadcn-хелпер
public/
  bud.svg                    бутон в шапке и фавиконка
```

Алиас `@/*` → `src/*` настроен в `vite.config.ts` (resolve.alias) и
`tsconfig.json` (compilerOptions.paths) — обычной shadcn-структуры
(`components.json`, `components/ui` как единственная точка входа для CLI)
в проекте нет, добавлены только `lib/utils.ts` и сам `components/ui/`,
без CLI. Если позже будете ставить компоненты через `npx shadcn add`,
эта пара файлов — то, что CLI ищет в первую очередь; без неё она
пересоздаст их сама с чужими настройками.

## Как поменять картинки

Фон каталога и текстура «Почему мы» — в `src/data/media.ts` (сейчас
Unsplash через их CDN). Фото букетов — в `src/data/products.ts`, каждое своим
полем `photo`. Больше нигде в коде URL изображений нет.

Hero — исключение: это не URL из `media.ts`, а два локальных файла в
`public/` — `hero-portal.mp4` (сгенерированный видео-луп: облака и голубь,
Higgsfield Seedance 2.5, image-to-video от референса из Nano Banana) и
`hero-portal.jpg` (первый кадр того же ролика, используется и как `poster`
на время загрузки видео, и как отдельная статичная картинка). Чтобы
заменить — кладёте новую пару файлов с теми же именами в `public/`,
`Hero.tsx` их не называет по-другому.

Видео и картинка идут двумя параллельными элементами с CSS-переключением,
а не одним `<video>` с фолбэком внутри: `motion-safe:block` /
`motion-reduce:block` (то же самое ядро Tailwind, что и `sm:`/`lg:`, просто
привязанное к `prefers-reduced-motion`, а не к ширине экрана) показывает
ровно один из двух. При включённом «уменьшить анимацию» в системе браузер
даже не запрашивает видеофайл — сразу рендерит статичную картинку, без
JS и без мигания при загрузке.

## Как поменять букеты

`src/data/products.ts` — массив `products`, реальный ассортимент
[grozflowers.ru](https://grozflowers.ru/), вытащенный из живого каталога
(2026-09-02). Тип `Product` описывает карточку целиком: `name` (название),
`note` (короткое описание — курсивом золотом над названием, та же
формулировка, что в исходном каталоге), `price`, необязательный `oldPrice`
(зачёркнутая цена + бейдж «Выгодно» — сейчас только у «Дофаминового букета
XL») и `photo`. Разметка карточки читает только эти поля.

Фото хотлинкаются напрямую с `grozflowers.ru/assets/...` — это фотобиблиотека
того же бизнеса, площадка та же, хотлинкинг безопасен. Интерактивный
конструктор цвета/упаковки с исходного сайта не портировался — там просто
одно фиксированное фото на карточку.

Кнопка «Заказать» на каждой карточке — не корзина, а прямая ссылка на
`t.me/GrozFlowers` с предзаполненным текстом (`telegramMessageLink` в
`src/data/contact.ts`): у исходного сайта нет ни настоящей корзины, ни
телефона, весь заказ идёт через чат в Telegram. Тот же хелпер используется в
CTA «Не нашли нужный букет?» под каталогом и в футере.

### Фильтр по категориям

`CATEGORIES` в `products.ts` — ровно вкладки исходного сайта: «Все», «Розы»,
«Кустовые», «Гортензии», «Корзины», «Пионы». У каждого товара есть
`category` того же типа (плюс отдельное значение `'Авторские'` — только у
«Дофаминового букета XL», без своей вкладки, как и на исходном сайте: он
виден лишь на «Все»).

Переключение фильтра **не убирает карточки из DOM** — скрытые товары
получают класс `hidden` (`display:none`), но остаются смонтированными.
Это принципиально: `useScrollReveal` наблюдает за элементами один раз при
монтировании и, показав карточку, отписывается от неё. Если бы карточки
пересоздавались через `.filter()` перед `.map()`, при возврате на вкладку
«Все» они бы всплывали уже без класса `revealed` — то есть навсегда
прозрачными, потому что второй раз наблюдатель их не увидит.

### Выравнивание карточек в ряду

Название у одних букетов — одна строка («51 роза»), у других — три
(«Гортензии и кустовые розы Classic»). Без специальной меры цена и кнопка
«Заказать» съезжали бы вниз ровно настолько, насколько длиннее заголовок,
и в рядах с карточками разной «многословности» ряд цен идёт вразнобой.

Решение — не выравнивание текста, а раскладка: `<article>` — `flex
flex-col`, грид держит `items-stretch` (по умолчанию), так что все карточки
в ряду и так растянуты до высоты самой высокой. Дальше внутри каждой
карточки текстовый блок ниже фото тоже `flex flex-col`, и у строки
цена+кнопка стоит `mt-auto` — она прижимается к низу растянутого блока
независимо от того, сколько места над ней занял заголовок. Если добавляете
новое поле в карточку (например, бейдж), проверьте, что оно не окажется
ниже этой строки — `mt-auto` "съедает" всё оставшееся место перед собой.

### Появление карточек при смене фильтра

Карточки не появляются и не пропадают из DOM при переключении вкладки —
скрытые получают `hidden` (`display:none`), но остаются смонтированными
(`products.map` рендерит все 17 всегда, `visible ? '' : 'hidden'`).

Но сама «плавность появления» (класс `revealed`, добавляющий CSS-анимацию)
у карточек управляется **не** общим `useScrollReveal` — это отдельная логика
в `Catalog.tsx` (`gridRevealed`, состояние React + свой `IntersectionObserver`
на грид). Причина: `Catalog` перерендеривается при каждом клике по фильтру,
пересчитывая `className` каждой карточки из `visible`. Если бы `revealed`
добавлялся императивно через `classList.add()` (как это делает
`useScrollReveal` для остального сайта), следующий же рендер, где у
карточки реально поменялась строка `className`, стирал бы его — React
переписывает атрибут `class` целиком, не зная о классе, добавленном мимо
него. Отсюда и баг: после нескольких переключений фильтра каталог мог
показаться пустым — карточки были на месте, но с `opacity: 0`.

Поэтому у карточек свой CSS-класс `card-reveal` (а не `reveal-scale`) —
`useScrollReveal` его не видит и не трогает. `revealed` добавляется в
`className` прямо в JSX, из `gridRevealed`, а это состояние один раз
становится `true` и больше никогда не сбрасывается — значит переживает
любое число последующих рендеров/фильтров. Если понадобится третий блок с
похожей раскладкой (карточки, которые то показываются, то прячутся), тот
же приём: своё состояние, свой класс, `revealed` вычисляется в JSX, а не
дописывается снаружи.

## Конфигуратор («Хит продаж»)

`FeaturedConfigurator.tsx`, между Hero и Каталогом — единственный
интерактивный товар на сайте, портированный с реального конструктора на
grozflowers.ru (там он открывался как отдельный виджет: размер/цвет/
упаковка, живое фото под выбор, цена пересчитывается на лету).

Все данные — в `src/data/featured.ts`, вытащены не из статичного каталога
исходного сайта (у него отдельные, более простые цифры на карточках), а
из его же JS-функций ценообразования (`getBasePrice`, `getOldPrice`),
вызванных прямо в браузере на живом сайте — это единственный надёжный
способ, тарифная сетка в `app.js` даёт не те числа, которые сайт реально
показывает (там есть более поздний хардкод поверх неё). Три размера, у
каждого своя пара цена/старая цена:

| Размер | Цена     | Старая цена |
| ------ | -------- | ----------- |
| 51 шт  | 7 900 ₽  | 11 300 ₽    |
| 101 шт | 12 900 ₽ | 18 400 ₽    |
| 151 шт | 16 900 ₽ | 24 100 ₽    |

Цвет и упаковка на цену не влияют (`extra: 0` у всех вариантов на
исходном сайте) — меняются только заголовок, фото и то, какие упаковки
вообще предлагаются (не у каждого цвета есть, например, голубая упаковка).
Если для выбранного цвета текущая упаковка недоступна, `FeaturedConfigurator`
сам переключает на `defaultPackage` этого цвета (`useEffect` на `color`).

Фото — тоже хотлинк с `grozflowers.ru/assets/...` (полная матрица размер ×
цвет × упаковка × ракурс реально существует на их сервере, проверено
запросами по всем трём размерам). Вкладка «Бутоны» — особый случай:
показывает один и тот же крупный план бутона для цвета независимо от
размера и упаковки (`featuredImage()` в `featured.ts` явно обрабатывает
`view === 'macro'` до всей остальной логики).

Стилистически это та же цветовая система, что и везде на сайте (кремовый/
чернильный/золото), а не розово-красная палитра оригинального виджета —
кружки-свотчи и пилюли размера используют тот же язык, что фильтры
категорий в Каталоге, чтобы не читаться как чужеродная вставка.

## Стыки секций

Первая версия пыталась *смешать* цвет одной секции с другой — растянутые
градиенты, нарисованный туман, полупрозрачная вуаль поверх размытого фото.
Проблема была структурная: у полупрозрачного слоя всегда есть точка, где он
недостаточно непрозрачен и сквозь него читается то, что под ним, будь то
фотография или просто другой оттенок фона. На разных высотах экрана и
разных фото эта точка оказывалась в разных местах — вслепую не поймать.

Сейчас на стыке стоит `Ribbon.tsx` — непрозрачная лента (28–36px по
брейкпоинтам), закрашенная реальной сгенерированной фото-текстурой
(`public/ribbon-velvet.jpg`: тёмный бархат с золотой прошивкой пунктиром,
уже впечатанной в саму фотографию) через `background-size: 100% 100%` —
растягивается точно под ширину блока независимо от исходных пропорций
фото, так что нет кропа, с которым пришлось бы бороться на разных ширинах
экрана. Раньше здесь был жаккардовый узор из веточек, потом — ручной
CSS-градиент под бархат; оба заменили на настоящую текстуру, потому что
градиентами убедительную глубину ткани нарисовать не получалось.

Была ещё попытка вернуть декоративный туман/свечение вокруг ленты
(`portal-mist.svg`, тот же приём, что в самой первой версии сайта) —
технически багов не было (кроме одного с анимацией, который тоже
починили), но когда туман наконец встал на своё место как надо, жёлтая
дымка вокруг ленты сама по себе выглядела плохо. Убрали совсем: лента
одна, без ореола, справляется со швом сама.

Просто третий элемент в потоке между секциями:

```
<Hero />
<Ribbon />
<FeaturedConfigurator />
<Catalog />
<Ribbon />
<Advantages />
```

Никаких отрицательных отступов и градиентов-компенсаторов: `Hero` —
h-screen с фото и тёмным скримом, все остальные — обычные секции с обычным
паддингом. Смешивать нечего — лента непрозрачна, поэтому ей всё равно, что
выше и что ниже. Между `FeaturedConfigurator` и `Catalog` ленты нет —
обе секции кремовые, смешивать нечего и без неё. Если понадобится ещё один
стык светлого с тёмным — тот же компонент, просто ещё один `<Ribbon />`.

`useGroundTone` (переключает Navbar/Footer между тёмным текстом и светлым)
берёт **все** секции с `data-ground="light"` (сейчас их две —
`FeaturedConfigurator` и `Catalog`) и считает их объединение: минимальный
`top` и максимальный `bottom` по всем сразу. Добавляете третью светлую
секцию — просто поставьте на неё тот же атрибут, пересчитывать вручную
ничего не нужно.

## Панели над разным фоном

Футеру нужны обе подложки сразу: тёмная над фото и зелёным, светлая над кремом.
Они наложены друг на друга и переключаются прозрачностью (`Footer.tsx`) — если
менять один градиент на другой вместо кросс-фейда, переход перестаёт
анимироваться.

## Пункты меню увеличиваются под курсором

`ui/magnetic-link.tsx` — тот же приём, что в док-панелях macOS: курсор ближе
к пункту меню — пункт крупнее, дальше — обычного размера, соседи затухают
плавно. Взято из референсного `ui/animated-dock.tsx` (сохранён как есть, но
в шапке не используется напрямую — там иконки в круглых капсулах растут по
ширине, у нас текстовые пункты, поэтому вместо ширины капсулы масштабируется
сам текст: тот же движок близости на `useTransform`/`useSpring`, только
управляет `scale`, а не `width`).

Один `mouseX` (`useMotionValue`) на весь `<nav>` в `Navbar.tsx`, обновляется
через `onMouseMove`/`onMouseLeave`, шарится между обоими списками ссылок —
близость чувствуется по всей плавающей капсуле, а не сбрасывается на
логотипе посередине. `MagneticLink` меряет расстояние от курсора до
собственного центра и внутри компонента, `range`/`peakScale` настраиваются
на конкретный пункт при необходимости (сейчас у всех одинаковые: пик ×1.16 в
радиусе 90px — сдержаннее, чем в референсе, вырви-глаз эффект здесь неуместен).

Мобильный список ссылок (`sm:hidden`) — обычные `<a>`, без `MagneticLink`:
у тач-экрана нет курсора, который может быть «рядом», так что эффект просто
никогда не сработает — сложность не нужна там, где её нечем показать.

Стоило дороже, чем кажется: `motion` — не маленькая зависимость. JS-бандл
вырос с ~173 КБ до ~329 КБ (gzip: 55 → 106 КБ) ради одного hover-эффекта в
шапке. Если это станет проблемой производительности — можно переписать тот
же приём на голом `requestAnimationFrame` + CSS-переменной без библиотеки,
логика в `magnetic-link.tsx` достаточно простая, чтобы это была separate
задача на час, а не переписывание с нуля.

## Что учтено

- `prefers-reduced-motion` выключает все анимации и параллакс;
- видимый фокус клавиатуры (золотая обводка);
- вёрстка от 375 px; сетка каталога 2 → 4 колонки.

## Известное ограничение Tailwind

Модификатор прозрачности работает только по стандартной шкале Tailwind
(`/5`, `/10`, … `/85`, `/90`, `/95`). `bg-[#faf6f0]/92` класс **не создаёт** —
цвет молча пропадает. Для промежуточных значений пишите значение целиком:
`bg-[rgba(250,246,240,0.93)]`.
